 성능 테스트
26.07.14 "성능 향상을 위한 병목 현상 가설 세우기"

### 1. 현재 시스템 현황
    - server : uvicorn workers -> 1개 (default)

    - cpu : aws ec2 vCPU -> 2코어 (t3 micro, 1GB)
    
    - db : sqlalchemy pool_size -> 5개 (default)
      * 특이사항 : db 엔진은 async 사용중  

    
### 2. 가설 및 예측  
    
    가설 : 현재 서버에서 일어나는 거의 모든 작업은 db조회에 그치기 때문에, I/O바운드이기 때문에,
          다른 어떤 곳들보다는 db에서 응답이나 처리를 어떻게 해주는지가 가장 중요함 -> pool_size가 
          다른 곳들보다 병목 현상에 가장 영향을 줄 확률이 높다고 볼 수 있다. (1차 병목)

          또한 cpu 코어는 2개, uvicorn workers는 1개이므로 처리량이 대폭 증가했을 때엔 db 응답
          이 효과적으로 처리되었다고 해도 cpu가 50%이상의 효율을 내지 못해 병목이 발생할 확률이 있다.
          (2차 병목)

          -> pool_size가 5이므로 동시 유저 5~10인 순간부터는 커넥션을 기다리는 시점이 발생해서 
            응답 시간이 늦어지고 1차 병목이 발생할 것이다. 5~10 정도인 상황에서는 cpu나 서버의 workers의 경우 아직 여유가 있는 상태일 것이다.

            pool_size를 확장시키더라도 30명 이상부터는 cpu를 효율적으로 사용하지 못해 2차 병목이 
            발생할 것이다.


    결론 : 유저 수 5명을 넘어서는 순간부터는 pool_size가 부족해 속도가 느려지고, 30명을 넘어서는 순간에서는 workers가 1개이므로 cpu가 성능을 다 내지 못해서 속도가 느려질 것이다.
